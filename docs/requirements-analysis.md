# AIFilmer MVP — 需求分析

> **文档版本**: v1.0  
> **状态**: 已批准（MVP 范围冻结）  
> **适用阶段**: MVP（Minimum Viable Product）  
> **目标平台**: iOS 旗舰机（iPhone 14 及以上）  
> **输出**: 软件需求规格说明，采用敏捷 User Story + Acceptance Criteria 格式

---

## 1. 项目背景与价值

### 1.1 背景
视频拍摄已成为大众日常记录生活的基本方式，但**拍出一段具有观赏价值的视频**有很高技术门槛。绝大多数日常记录只停留在"留影"阶段，无法被二次消费或分享。同时，**短视频专业博主**每天会浪费大量精力在重复性素材拍摄上，产生大量"废片"。

核心矛盾：**专业镜头的复杂度** vs **大众用户的拍摄能力**之间存在巨大鸿沟。

### 1.2 产品愿景
AIFilmer 让 AI 接管"拍摄决策"——用户保留**指向权**（手持移动设备），AI 保留**拍摄权**（构图、调色、参数、下一分镜、镜头语言）。理想体验：

> 用户输入一段"想拍的主题"，将镜头对准第一个镜头的拍摄内容，AI 即开始**自主识别场景、构图、调色、调参，并引导用户进入下一个分镜**，形成一套完整的镜头语言。

### 1.3 MVP 价值主张
- 把"AI 摄影师"这一概念**真正落到一台手机里**
- 用最克制的功能集合，证明"AI 自主拍摄"对真实拍摄体验有**可感知的提升**
- 为后续版本（云台、运镜决策、剪辑、语音交互）打下**协议与架构基线**

## 2. 范围（In-Scope / Out-of-Scope）

### 2.1 ✅ MVP 范围内（In-Scope）

| 维度 | 范围 |
|---|---|
| 设备 | iOS 旗舰机（iPhone 14 及以上），单设备 |
| 算力 | 端侧为主（实时感知 + 微调），云侧为备（LLM 拆镜本、MLLM 主体匹配） |
| 交互 | 文字输入主题 + UI 推荐/确认/修改下一镜头 |
| 拍摄 | 单设备多镜头连续拍摄（每个镜头由 AI 自主控制） |
| 录制 | 1080p 本地视频录制 |
| 演示场景 | 人物特写 / 风景静物 / Vlog 中景 |

### 2.2 ❌ MVP 范围外（Out-of-Scope，YAGNI）

- 语音交互（ASR / TTS / 多轮对话 / VAD）
- 防抖与抖动检测（依赖手机 OIS + EIS 系统级能力）
- 云台控制（DJI / 智云等）
- 手动接管模式（手动曝光 / 对焦 / 手动快门）
- 复杂运镜决策（推 / 拉 / 摇 / 移 等镜头运动的 AI 主动控制）
- 视频后期剪辑 / 拼接 / 调色后处理
- Android 平台支持（MVP 暂不交付）
- 多机位协同

## 3. 用户角色与典型用户

| 角色 | 描述 | MVP 关注度 |
|---|---|---|
| **C 端普通用户** | 想拍出更好看的日常视频，但缺乏摄影/剪辑能力 | 主要用户 |
| **短视频内容创作者** | 每天重复拍摄固定脚本，渴望降低废片率 | 主要用户 |
| **早期尝鲜者（评测 / KOL）** | 关注 AI 拍摄新形态 | 次要用户 |

## 4. 用户故事（User Stories）

### Epic-1 主题输入与脚本生成

**US-1.1 输入主题**  
**作为** C 端用户，**我想要**输入一段文字描述我想拍的主题（如"夕阳下的咖啡店"），**以便**让 AI 帮我规划接下来的拍摄。

**验收标准**：
- [ ] App 启动后主界面提供"主题输入框"
- [ ] 用户输入主题后，点"生成脚本"按钮
- [ ] 按钮按下后显示加载状态
- [ ] 在网络良好的情况下，5 秒内返回 N 个镜头（2 ≤ N ≤ 8）的脚本
- [ ] 脚本以结构化卡片形式展示（镜号 / 类型 / 主体 / 时长 / 调色意图 / 镜头运动）
- [ ] 每个镜头卡片可单独"查看详情 / 重新生成"
- [ ] 网络异常时显示明确错误提示，可重试

**US-1.2 修改单个镜头**  
**作为** 用户，**我想要**对生成的某一个镜头不满意时单独修改它，**以便**保留其他镜头不动。

**验收标准**：
- [ ] 每个镜头卡片有"修改"入口
- [ ] 修改支持：自然语言指令（如"这个镜头再近一点"）
- [ ] 修改只影响该镜头，其他镜头保持不变
- [ ] 修改结果在 3 秒内返回

**US-1.3 整体重新生成**  
**作为** 用户，**我想要**对整组镜头都不满意时一键重生成。

**验收标准**：
- [ ] 脚本页提供"重新生成"按钮
- [ ] 重生成时显示加载状态
- [ ] 重生成结果完全替换当前脚本
- [ ] 提供"撤销"回到上一版

---

### Epic-2 镜头拍摄执行

**US-2.1 启动第一个镜头**  
**作为** 用户，**我想要**把镜头对准第一个镜头的拍摄主体并点击"开始"，**以便**让 AI 介入拍摄。

**验收标准**：
- [ ] 当前镜头卡片显示"将镜头对准：___"提示与目标主体描述
- [ ] 点击"开始"按钮触发 AI 介入
- [ ] 进入拍摄状态后，HUD 实时显示 AI 当前决策（如"识别中：人脸"）

**US-2.2 AI 自主调参**  
**作为** 用户，**我想要** AI 在拍摄过程中自动调整曝光、白平衡、对焦等参数，**以便**我不需要手动操作也能拍出好看的画面。

**验收标准**：
- [ ] AI 持续跟踪主体（人脸 / 物体），并把对焦点保持在主体上
- [ ] AI 根据场景（户外 / 室内 / 逆光 / 夜景）自动调整曝光与白平衡
- [ ] 调参不会"抽风"——参数变化有惯性，EV 死区 ±0.3 内不动作
- [ ] 主体跟踪在 30 fps 下稳定（不跳、不漂移）

**US-2.3 AI 主动调色**  
**作为** 用户，**我想要** AI 根据脚本中的"调色意图"主动调色（不是建议），**以便**镜头之间风格统一、整体成片有调性。

**验收标准**：
- [ ] AI 在拍摄期间持续应用当前镜头的 LUT
- [ ] 调色变化平滑（不闪烁、不突变）
- [ ] 调色范围受限：色温偏移 ≤ ±15%、饱和度 80~120%，不会导致肤色严重偏色
- [ ] 整段共用一份 StyleProfile，镜头切换时不"跳色"

**US-2.4 AI 识别场景**  
**作为** 用户，**我想要**屏幕实时显示 AI 当前识别到了什么场景和主体，**以便**我知道 AI 在想什么、信任它在做事。

**验收标准**：
- [ ] HUD 持续显示：当前场景分类（如"人像 / 风景 / 夜景"）+ 主体描述（如"脸部主体 0.92"）
- [ ] 当场景或主体变化时，HUD 实时更新（延迟 ≤ 500ms）

---

### Epic-3 多镜头连续拍摄

**US-3.1 当前镜头完成 → 推荐下一镜头**  
**作为** 用户，**我想要**当前镜头拍完后自动看到下一个镜头的提示，**以便**我知道接下来要拍什么。

**验收标准**：
- [ ] 当前镜头达到计划时长（±10%）时，自动弹出"下一镜头"提示卡
- [ ] 提示卡显示：镜号 / 类型 / 主体描述 / 调色意图 / 三维方向提示
- [ ] 用户可手动点击"立即结束当前镜头"提前进入下一镜头

**US-3.2 三维方向提示（核心差异化）**  
**作为** 用户，**我想要** 知道下一个镜头的拍摄主体在哪里（前后左右上下），**以便**我能准确地把镜头对准它。

**验收标准**：
- [ ] 若目标主体已在当前画面内：提示"向左一点 / 向右一点 / 居中"等画面内相对位置
- [ ] 若目标主体不在画面内：提示"请向左/右/上/下旋转手机寻找：___"
- [ ] 提示具有收敛性：每给一次方向提示都基于"上一帧 → 当前帧"偏差，避免越走越偏

**US-3.3 接受 / 跳过 / 修改下一镜头**  
**作为** 用户，**我想要**对 AI 推荐的下一个镜头有完全控制权。

**验收标准**：
- [ ] 下一镜头提示卡提供三个动作按钮：接受 / 跳过 / 修改
- [ ] 接受：进入该镜头的拍摄状态
- [ ] 跳过：跳到再下一个镜头
- [ ] 修改：自然语言指令微调该镜头（触发 LLM 重写）

---

### Epic-4 视频录制与本地存储

**US-4.1 连续录制**  
**作为** 用户，**我想要** AI 控制期间所有镜头被无缝录制为一个连续视频文件，**以便**事后能直接分享成片。

**验收标准**：
- [ ] 从首个"开始"到最后一个镜头结束，全程连续录制
- [ ] 输出 1080p / 30 fps H.264 视频文件
- [ ] 单次录制时长支持 ≥ 10 分钟，不丢帧
- [ ] 录制结束后文件保存在 App 沙盒内

**US-4.2 历史视频管理**  
**作为** 用户，**我想要**查看、回放、删除我拍过的视频。

**验收标准**：
- [ ] App 提供"我的作品"列表页
- [ ] 每个作品显示缩略图、主题、拍摄时长
- [ ] 支持点击播放、滑动删除
- [ ] 删除有二次确认

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标 |
|---|---|
| Fast Loop 端到端延迟 | ≤ 500ms（从采集到调参生效） |
| 场景识别 / 主体检测 | ≤ 50ms / 帧，端侧 NPU |
| Creative Loop 决策周期 | 1~3s |
| LLM 拆镜本响应 | ≤ 5s（网络良好） |
| 视频录制掉帧率 | ≤ 0.1% |

### 5.2 可用性

| 指标 | 目标 |
|---|---|
| 学习成本 | 新用户 30 秒内理解"点开始拍摄"主流程 |
| 主流程成功率 | ≥ 95%（不包含用户主动取消） |
| 错误可恢复性 | 所有失败有明确提示，可重试 |

### 5.3 兼容性

| 维度 | 目标 |
|---|---|
| iOS 版本 | iOS 17 及以上 |
| 设备 | iPhone 14 / 14 Pro / 15 / 15 Pro / 16 系列（首批白名单） |
| 网络 | Wi-Fi / 蜂窝网络均可，断网时核心功能仍可用 |

### 5.4 隐私与合规

- 视频数据**仅在用户设备本地存储**，不上传云端
- 上传云侧的只有：脚本生成请求、主体匹配请求（图片可裁剪至仅含主体）
- 用户可在首次启动时关闭"上传图片到云侧"的选项
- App Store 隐私政策、相机权限文案、麦克风权限文案（MVP 不使用麦克风，但需预留）

### 5.5 可维护性

- 端侧模型按需下载（首次启动按场景下载），支持热更新
- 后端 LLM 服务可独立升级不影响客户端
- Shot Protocol（MCP-like）有版本号，向后兼容

## 6. 风险与缓解（高层视角）

| 风险 ID | 风险点 | 等级 | 缓解措施 |
|---|---|---|---|
| **R1** | 端到端延迟超预算 | 🔴 关键 | 严格端侧优先；Fast Loop 不依赖网络；预留性能预算 |
| **R2** | iOS 不同机型 API 不一致 | 🔴 关键 | 设备白名单 + CI 设备矩阵 |
| **R3** | LLM 拆镜本输出不稳定 | 🔴 关键 | JSON schema 严格校验 + 自动 retry + 模板快路径兜底 |
| **R4** | HUD 不显示 AI 在做什么 | 🟡 高 | 强制 HUD 实时显示 AI 当前决策 |
| **R5** | 自动调参过度频繁 | 🟡 高 | 调参有惯性 + EV 死区 ±0.3 |
| **R6** | 跟踪抖动 | 🟡 高 | 卡尔曼 / EMA 平滑，禁止单帧切换对焦点 |
| **R7** | 调色导致肤色失真 | 🟡 高 | LUT 参数有上限 |
| **R8** | LLM API 成本不可控 | 🟢 中 | 模板快路径 + 本地小模型兜底 + 用户配额 |
| **R9** | 端侧模型分发 | 🟢 中 | 按需下载 + 支持热更新 |
| **R10** | 录制与推理争资源 | 🟢 中 | 录制降级 + NPU 隔离 + 内存峰值预算 |

> 详细技术风险见《概要设计》和《详细设计》。

## 7. 验收标准（MVP Done 定义）

MVP 在以下条件全部满足时视为完成：

1. ✅ 上述所有 User Story 的验收标准全部通过
2. ✅ 演示三类场景（人物特写 / 风景静物 / Vlog 中景）连续拍摄成功率 ≥ 90%
3. ✅ Fast Loop 端到端延迟 ≤ 500ms（在白名单设备上）
4. ✅ App 通过 TestFlight 内测
5. ✅ 通过隐私合规审核与 App Store 上架审核
6. ✅ 完整的需求分析、概要设计、详细设计文档与 HTML 页面就绪
