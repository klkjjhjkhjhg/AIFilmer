🎬 AIFilmer MVP — 需求分析

让 AI 接管"拍摄决策"，把 iPhone 变成自主摄影师
📄 v1.0 已批准 🎯 MVP 范围冻结 📱 iOS 旗舰机（iPhone 14+） 🤖 端云协同

1. 项目背景与价值

背景：视频拍摄已成为大众日常记录的基本方式，但拍出"具有观赏价值"的视频有很高技术门槛。绝大多数日常记录停留在"留影"阶段；短视频博主每天浪费大量精力在重复拍摄上，产生大量"废片"。

产品愿景：AIFilmer 让 AI 接管拍摄决策——用户保留指向权，AI 保留拍摄权（构图、调色、参数、下一分镜、镜头语言）。

MVP 价值主张：把"AI 摄影师"概念真正落到一台手机里，用最克制的功能集合证明"AI 自主拍摄"对真实拍摄体验有可感知的提升。

2. 范围

✅ MVP 范围内（In-Scope）

  • 设备：iOS 旗舰机（iPhone 14+），单设备
  • 算力：端侧为主（实时感知 + 微调），云侧为备（LLM 拆镜本、MLLM 主体匹配）
  • 交互：文字输入主题 + UI 推荐/确认/修改下一镜头
  • 拍摄：单设备多镜头连续拍摄（每个镜头由 AI 自主控制）
  • 录制：1080p 本地视频录制
  • 演示场景：人物特写 / 风景静物 / Vlog 中景

❌ MVP 范围外（Out-of-Scope）

  • 语音交互（ASR / TTS / 多轮对话 / VAD）
  • 防抖与抖动检测（依赖手机 OIS + EIS 系统级能力）
  • 云台控制（DJI / 智云等）
  • 手动接管模式（手动曝光 / 对焦 / 手动快门）
  • 复杂运镜决策（推 / 拉 / 摇 / 移）
  • 视频后期剪辑 / 拼接 / 调色后处理
  • Android 平台支持
  • 多机位协同

3. 用户角色

角色描述MVP 关注度

4. 用户故事

Epic-1 主题输入与脚本生成

US-1.1
输入主题
作为 C 端用户，我想要输入一段文字描述我想拍的主题，以便让 AI 帮我规划拍摄。
  • 主界面提供"主题输入框"+"生成脚本"按钮
  • 5 秒内返回 2~8 个镜头的脚本
  • 每个镜头以结构化卡片展示（镜号 / 类型 / 主体 / 时长 / 调色意图 / 镜头运动）
  • 支持"查看详情 / 重新生成"
US-1.2
修改单个镜头
作为 用户，我想要对单个镜头不满意时单独修改它。
  • 每个镜头卡片有"修改"入口，支持自然语言指令（如"再近一点"）
  • 修改只影响该镜头，3 秒内返回结果
US-1.3
整体重新生成
对整组镜头一键重新生成；支持撤销。

Epic-2 镜头拍摄执行

US-2.1
启动第一个镜头
用户把镜头对准第一个镜头的拍摄主体并点击"开始"，AI 介入拍摄，HUD 实时显示 AI 当前决策。
US-2.2
AI 自主调参
AI 在拍摄过程中自动调整曝光、白平衡、对焦等参数。调参不会"抽风"——参数变化有惯性，EV 死区 ±0.3 内不动作。主体跟踪 30 fps 下稳定。
US-2.3
AI 主动调色
AI 根据脚本中的"调色意图"主动调色（不是建议）。调色平滑、有上限（色温 ≤ ±15%、饱和度 80~120%），不破坏肤色。整段共用一份 StyleProfile。
US-2.4
AI 识别场景可视化
HUD 持续显示当前场景分类与主体描述，变化延迟 ≤ 500ms。

Epic-3 多镜头连续拍摄

US-3.1
当前镜头完成 → 推荐下一镜头
当前镜头达到计划时长（±10%）时，自动弹出"下一镜头"提示卡。用户可手动"立即结束当前镜头"提前进入下一镜头。
US-3.2
三维方向提示（核心差异化）
下一个镜头的拍摄主体在哪里？
  • 若主体已在画面内：提示"向左一点 / 向右一点 / 居中"
  • 若主体不在画面内：提示"请向左/右/上/下旋转手机寻找：___"
  • 提示具有收敛性：每给一次方向提示都基于"上一帧 → 当前帧"偏差
US-3.3
接受 / 跳过 / 修改下一镜头
提示卡提供三个动作：接受 / 跳过 / 修改。修改触发 LLM 重写该镜头。

Epic-4 视频录制与本地存储

US-4.1
连续录制
从首个"开始"到最后一个镜头结束，全程连续录制。1080p / 30fps H.264，支持 ≥ 10 分钟。
US-4.2
历史视频管理
"我的作品"列表页：缩略图 / 主题 / 时长；支持播放 / 删除（二次确认）。

6. 风险与缓解（高层视角）

ID风险点等级缓解措施
R1端到端延迟超预算🔴 关键严格端侧优先；Fast Loop 不依赖网络
R2iOS 不同机型 API 不一致🔴 关键设备白名单 + CI 设备矩阵
R3LLM 拆镜本输出不稳定🔴 关键JSON schema 严格校验 + retry + 模板兜底
R4HUD 不显示 AI 在做什么🟡 高强制 HUD 实时显示 AI 决策
R5自动调参过度频繁🟡 高调参有惯性 + EV 死区 ±0.3
R6跟踪抖动🟡 高卡尔曼 / EMA 平滑
R7调色导致肤色失真🟡 高LUT 参数有上限
R8LLM API 成本不可控🟢 中模板快路径 + 本地小模型 + 用户配额
R9端侧模型分发🟢 中按需下载 + 热更新
R10录制与推理争资源🟢 中录制降级 + NPU 隔离 + 内存预算

7. 验收标准（MVP Done 定义）

  1. 所有 User Story 验收标准全部通过
  2. 三类演示场景连续拍摄成功率 ≥ 90%
  3. Fast Loop 端到端延迟 ≤ 500ms（白名单设备）
  4. App 通过 TestFlight 内测
  5. 通过隐私合规与 App Store 上架审核
  6. 完整的文档与 HTML 页面就绪

附录：术语表

  • Fast Loop：端侧实时感知与微调闭环（≤ 500ms）
  • Creative Loop：云侧/端侧协同的创意决策闭环（1~3s）
  • Shot Protocol：LLM 输出到执行层的协议层（MCP-like）
  • StyleProfile：整段视频共用的调色风格基线
  • LUT：Look-Up Table，色彩查找表
  • NPU：Neural Processing Unit，端侧神经网络加速器
